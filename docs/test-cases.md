# SnapShop — 标准操作路径测试用例

> 基于 START_HERE.md 第 4 节「最小功能验证（6 条路径）」扩展，覆盖全部核心用户操作路径。

---

## 前置条件（执行任意测试用例前必须满足）

1. **后端已启动**：`curl http://<后端地址>/health` 返回 `{"status":"healthy"}`
2. **App 已配置后端地址**：Release APK 需在构建前修改 `snapshop/lib/core/network/api_client.dart` 第 105 行的 `_productionBaseUrl`，指向实际后端地址（详见 START_HERE.md 8.6.2 节）
3. **AI 服务可用**：后端 `.env` 中 `AI_MOCK_MODE=false`，火山方舟 VLM/LLM 密钥有效
4. **（ADB 方式）端口转发**：若 App 使用 `localhost` 地址且手机通过 USB 连接，需执行 `adb reverse tcp:8000 tcp:8000`

---

## TC001: 拍照识物全流程

- **前置条件**: App 已连接后端服务，后端 `.env` 中 `AI_MOCK_MODE=false`，火山方舟 VLM/LLM 密钥有效
- **操作步骤**:
  1. 启动 SnapShop App，进入首页
  2. 确认首页显示品牌 Logo 和搜索栏
  3. 点击搜索栏左侧 **📷 相机图标**
  4. 系统唤起原生相机，对任意实体商品（如耳机、水杯、鞋子）拍照
  5. 拍摄完成后自动跳转至识别结果页
  6. 等待识别完成（含 VLM 识别 + 多平台商品检索 + LLM 建议生成）
- **预期结果**: VLM 识别成功，页面显示：类目 + 属性标签 + 建议卡片 + 商品列表
- **验证点**:
  - [ ] 属性标签数量 ≥ 3（如品牌、颜色、风格、材质等）
  - [ ] 建议卡片数量 3–6（如"查看同款低价""只看旗舰店"等）
  - [ ] 商品列表非空，至少覆盖 2 个平台（京东 / 拼多多）
  - [ ] 每张商品卡片显示：商品名、价格、平台标识、店铺名
  - [ ] 价格汇总栏显示最低价和均价
  - [ ] 会话成功持久化，可通过 `/api/v1/history` 查询

## TC002: 相册选图识别

- **前置条件**: 设备相册中已有至少一张商品图片，App 已连接后端服务
- **操作步骤**:
  1. 在首页点击搜索栏右侧 **🖼️ 相册按钮**
  2. 搜索栏向上抬升，露出相册图片网格
  3. 点击任意一张已存储的商品图片
  4. 图片上传后跳转至识别结果页
  5. 等待识别完成
- **预期结果**: 与 TC001 步骤 4–6 相同，识别结果页正常展示
- **验证点**:
  - [ ] 搜索栏抬升动画流畅，相册网格正确加载
  - [ ] 图片上传成功（HTTP 200）
  - [ ] 属性标签数量 ≥ 3
  - [ ] 建议卡片数量 3–6
  - [ ] 商品列表非空
  - [ ] 再次点击相册按钮可关闭相册（按钮变为关闭图标）

## TC003: 智能建议卡片交互

- **前置条件**: 已完成 TC001 或 TC002 的识别流程，停留在识别结果页，建议卡片区域可见
- **操作步骤**:
  1. 确认建议卡片区域有 3–6 张卡片
  2. 点击"按价格排序"建议卡片 → 验证商品列表按价格从低到高排序
  3. 点击"只看旗舰店"建议卡片 → 验证商品列表过滤为仅显示官方旗舰店商品
  4. 点击"查看同款低价"建议卡片 → 验证商品列表聚焦同款低价商品
  5. （如存在）点击其他动态生成的建议卡片 → 验证每种卡片点击后商品列表正确刷新
- **预期结果**: 每种建议卡片点击后，商品列表按对应规则过滤/排序，结果正确
- **验证点**:
  - [ ] 每张建议卡片可点击，点击后有视觉反馈
  - [ ] 点击后商品列表正确过滤或重新排序
  - [ ] 多个建议卡片可连续点击，状态正确切换
  - [ ] `POST /api/v1/suggestions/action` 返回 HTTP 200 且 products 非空
  - [ ] 建议卡片标题、图标与 action_type 匹配

## TC004: 自然语言筛选（SSE 流式）

- **前置条件**: 已完成识别流程，停留在识别结果页，筛选输入栏可见
- **操作步骤**:
  1. 在筛选输入栏中输入自然语言条件，如"只要黑色的，500以内"
  2. 点击发送按钮
  3. 观察商品列表区域，商品卡片应逐条流入（而非一次性全量刷新）
  4. 等待 SSE 流推送完成（收到 `type: done` 事件）
- **预期结果**: SSE 流式逐条推送新商品，列表增量更新，最终显示黑色且价格低于 500 的商品
- **验证点**:
  - [ ] SSE 连接建立成功（HTTP 200 + `text/event-stream` Content-Type）
  - [ ] 首条 `type: parsing` 事件包含正确的筛选参数解析（如 `price_max: 500`, `color: 黑色`）
  - [ ] 商品卡片逐条流入（非全列表闪烁替换）
  - [ ] 最终 `type: done` 事件正确发出
  - [ ] 筛选结果中所有商品颜色含"黑色"，价格 ≤ 500
  - [ ] 输入更复杂的条件如"评价4.5以上"、"只要京东的"等，均能正确过滤

## TC005: 属性修正

- **前置条件**: 已完成识别流程，识别结果页显示属性标签（如"蓝色"、"休闲"等）
- **操作步骤**:
  1. 确认识别结果页顶部显示属性标签
  2. 点击颜色属性标签（如"蓝色"）
  3. 观察到弹出属性编辑面板（BottomSheet）
  4. 将颜色修改为"黑色"，点击确认按钮
  5. 观察商品列表自动刷新
- **预期结果**: 属性修正后触发重新搜索，商品列表更新为黑色相关商品
- **验证点**:
  - [ ] 属性标签可点击，点击后弹出编辑面板
  - [ ] 编辑面板支持任意文本输入（不限于预设选项）
  - [ ] 确认后 `PATCH /api/v1/recognize/{session_id}/attributes` 返回 HTTP 200
  - [ ] 商品列表正确更新为新属性对应的商品
  - [ ] 属性修正不调用 LLM，速度应明显快于完整识别流程
  - [ ] 可连续修正多个属性，每次修正后列表正确刷新

## TC006: 文字搜索（不拍照）

- **前置条件**: App 已连接后端服务，处于首页
- **操作步骤**:
  1. 在首页搜索栏中输入关键词，如"蓝牙耳机"
  2. 点击发送按钮（或键盘回车）
  3. 跳过拍照步骤，直接跳转至识别结果页
  4. 查看结果页展示
- **预期结果**: 跳过 VLM 识别，直接显示关键词检索结果，含预设建议卡片
- **验证点**:
  - [ ] `POST /api/v1/search` 返回 HTTP 200，响应时间明显短于 TC001（无 VLM 阶段）
  - [ ] 返回 JSON 中含 session_id、suggestions、products
  - [ ] 属性标签区域显示由 LLM 从关键词推导的临时属性（如 category="蓝牙耳机"）
  - [ ] 建议卡片为预设固定卡片（如"查看同款低价""只看官方旗舰店"），不含 AI 幻觉内容
  - [ ] 商品列表非空，商品标题含"蓝牙耳机"关键词
  - [ ] 后续可在该会话中正常使用属性修正和流式筛选功能
  - [ ] 测试空关键词（输入框为空时点击发送）：应返回 400 错误 `keywords不可为空`
