# AI 拍照识物与智能比价购物助手 — 产品需求文档 (PRD)

> **产品名称**：SnapShop | **版本**：v1.0 | **日期**：2026-05-23

---

## 1. 产品概述

### 1.1 背景与问题
在日常生活中，用户常遇到「看到想买但难以检索」的问题：面对街头同款服饰、短视频里的数码产品，往往缺少品牌/款式等关键信息；即使使用截图或以图搜图，也容易出现匹配不准、结果过多、跨平台比价成本高等情况，影响决策效率。

### 1.2 产品定位
一款面向 C 端消费者的 AI 拍照识物购物助手，通过 AI 技术打通「识别—检索—决策」全链路，用户完成一次拍摄后，系统可识别商品并聚合多平台推荐结果，同时支持自然语言追加筛选，辅助用户快速收敛候选并完成决策。

### 1.3 核心价值
- **降低检索门槛**：拍照即搜，无需手动输入复杂关键词
- **聚合比价效率**：一键获取多平台价格对比，无需逐个打开电商 App
- **智能决策引导**：动态生成建议卡片，降低用户决策成本
- **自然语言交互**：用日常语言筛选商品，无需学习复杂筛选器

## 2. 目标用户与使用场景

### 2.1 目标用户画像
| 用户类型 | 特征 | 核心需求 |
|---------|------|---------|
| 潮流购物者 | 关注服饰鞋包，经常刷短视频种草 | 快速找到同款，对比全网最低价 |
| 数码爱好者 | 关注 3C 产品，对价格敏感 | 跨平台比价，查看历史价格走势（远期扩展） |
| 日常消费者 | 非计划性购物，看到喜欢的就想买 | 快速识别商品，获取靠谱购买建议 |

### 2.2 典型使用场景
1. **街头偶遇场景**：用户在街上看到路人穿的好看运动鞋，掏出手机拍一张，立刻识别出品牌型号，全网比价
2. **短视频种草场景**：刷短视频看到博主推荐的连衣裙，截图上传，立刻找到同款不同价的所有选项
3. **线下逛店场景**：在实体店看到心仪商品，拍一张照片，立刻查到线上更低价格

## 4. 详细功能需求

### 4.1 首页模块（底部搜索栏主导）

#### 4.1.1 功能描述
首页采用三层视觉布局（顶部按钮栏 + 中央品牌 Logo + 底部搜索栏），配合向右滑动手势打开历史记录抽屉面板，支持四种启动方式。

#### 4.1.2 交互细节
| 状态 | 描述 |
|------|------|
| 默认状态 | 底部固定显示搜索栏，左侧相机图标，右侧相册按钮。顶部菜单按钮（打开历史抽屉）和设置按钮（跳转设置页），中央展示 SnapShop 品牌渐变 Logo 和标语"拍照识物 · 智能比价"，配合进场动效（Logo 下落弹入 + 搜索栏上浮走入 + 光晕消退） |
| 点击左侧相机图标 | 直接唤起系统原生相机，跳过中间页面，用户拍摄后进入预览确认 |
| 点击右侧相册按钮 | 底部搜索栏平滑向上抬升，下方露出系统相册图片选择网格，选择图片后搜索栏回落 |
| 文字输入 | 点击搜索栏中间区域，弹出键盘，输入商品描述后直接搜索。**文字搜索路径跳过 VLM 视觉识别环节**，直接进入关键词级商品检索（与相机/相册路径不同，后者需先经 VLM 识别再检索） |
| 菜单按钮 | 左上角菜单按钮（☰），点击打开历史记录抽屉面板，展示搜索记录和浏览记录 |
| 设置按钮 | 右上角设置按钮（⚙），点击跳转至设置页面 |

#### 4.1.3 验收标准
- [ ] 底部搜索栏在所有页面状态下不被遮挡
- [ ] 点击相册按钮时，搜索栏抬升动画流畅（300ms 缓动曲线）
- [ ] 相册选择网格支持横向滚动，展示最近 20 张图片
- [ ] 历史搜索记录按时间倒序排列，点击可快速重新搜索
- [ ] 向右滑动手势可打开历史记录抽屉面板（主页右移 305px + 圆角阴影），再次滑动或点击遮罩关闭
- [ ] 品牌 Logo 区域显示 SnapShop 渐变文字和标语，进场动效流畅播放，返回首页时重新播放

### 4.2 拍照识物功能

#### 4.2.1 功能描述
用户通过相机拍摄商品图片，服务端 VLM 视觉模型识别出商品的类目、品牌、颜色、风格等关键属性。

#### 4.2.2 识别输出字段
| 字段 | 类型 | 说明 |
|------|------|------|
| category | string | 三级类目，如「运动鞋/连衣裙/T恤/双肩包/蓝牙耳机」 |
| brand | string / null | 识别到的品牌名，未识别则为 null |
| color | string | 主要颜色，如「黑色/白色/蓝色」 |
| style | string | 风格描述，如「休闲/商务/运动/复古」 |
| material | string | 材质，如「皮革/纯棉/尼龙」 |
| shape | string | 造型特征，如「圆领/高帮/方形」 |
| keywords | array[string] | 检索用关键词列表，中英混合 |
| confidence | object | 各属性置信度，低置信度属性高亮提示用户确认 |

#### 4.2.3 验收标准
- [ ] 图片上传前自动压缩至 ≤2MB，避免大文件上传超时
- [ ] 识别过程展示友好 Loading 动画，提示「AI 正在识别商品...」
- [ ] 识别结果以标签形式展示，低置信度标签显示黄色感叹号提示
- [ ] 识别失败时展示友好错误页，提供重试按钮

### 4.3 属性修正功能

#### 4.3.1 功能描述
用户可以点击任意识别出的属性标签，弹出编辑面板修改属性值，修改后系统自动重新检索商品。

#### 4.3.2 交互流程
1. 用户点击任意属性标签（如「蓝色」）
2. 弹出底部半屏编辑 Sheet
3. 用户输入新的属性值（如「深蓝色」）
4. 点击确认，系统合并新属性重新检索商品列表

#### 4.3.3 属性修正反哺闭环
当用户频繁将 VLM 识别的「蓝色」手动修正为「深蓝色」时：
1. 界面上该属性的黄色感叹号（低置信度提示）自动转为正常的高亮绿标
2. 此会话后续的「自然语言追加筛选」自动将上下文中的颜色基准同步更新为「深蓝色」，防止 AI 在后续对话中产生幻觉
3. 属性修正为纯结构化数据操作：前端直接携带修正后的键值对请求后端检索接口，后端直接组装关键词进行电商API查询，完全不调用LLM，速度更快，无额外Token开销

#### 4.3.4 验收标准
- [ ] 属性编辑 Sheet 支持自由文本输入，不限制预设选项
- [ ] 属性修正后不重新调用 VLM 识别图片，仅走关键词重新检索，速度更快
- [ ] 修正后的属性标签实时更新展示
- [ ] 用户修正后的属性自动同步到会话上下文，后续筛选继承该基准

### 4.4 智能建议卡片功能

#### 4.4.1 功能描述
识别完成后，LLM 根据识别结果和商品召回量，动态生成 3-6 张可交互的建议卡片，横向滚动展示在识别结果下方。

#### 4.4.2 预设卡片类型
| 卡片标题 | 图标 | 动作类型 | 说明 |
|---------|------|---------|------|
| 查看同款低价 | price_down | sort | 按价格从低到高排序 |
| 只看官方旗舰店 | verified | filter | 过滤仅展示官方旗舰店商品 |
| 相似风格推荐 | style | filter | 扩展相似风格商品 |
| 按价格筛选 | price_range | filter | 弹出价格区间选择器 |
| 查看历史价格走势 | chart | navigate | 跳转价格趋势页（远期扩展） |
| 筛选：颜色/品牌/尺码 | filter_list | filter | 根据当前品类动态生成颜色/品牌/尺码筛选入口，LLM 根据召回结果自动生成 |

#### 4.4.3 动态生成规则
- 价格跨度大（max/min > 3）→ 生成「按预算筛选」卡片
- 品牌不置信 / 颜色多样 / 尺码不确定 → 生成「筛选：颜色/品牌/尺码」卡片
- 平台分散 → 生成「只看某平台」卡片
- **省钱决策卡片**：如果拼多多价格明显低于淘宝京东，动态生成「跨平台全网最低价在拼多多，是否一键前往？」
- **服务决策卡片**：如果用户拍的是贵重 3C 数码，动态生成「只看京东自营（含延保服务）」

#### 4.4.4 验收标准
- [ ] 建议卡片横向滚动，超出屏幕部分可滑动查看
- [ ] 点击任意卡片立即执行对应动作，商品列表实时刷新
- [ ] 卡片生成过程展示 Loading，不阻塞主界面

### 4.7 自然语言追加筛选功能

#### 4.7.1 功能描述
用户在商品列表页的输入框中用日常自然语言描述筛选条件，系统实时解析并通过 SSE 流式推送筛选后的商品结果。

#### 4.7.2 典型筛选示例
| 用户输入 | 解析出的结构化参数 |
|---------|-------------------|
| 帮我找 1000 元以内的黑色款，评价 4.8 分以上 | price_max: 1000, color: "黑色", min_rating: 4.8 |
| 只看自营的，价格从低到高 | shop_type: "self_operated", sort_by: "price_asc" |
| 500 元以下的白色连衣裙 | price_max: 500, color: "白色", category: "连衣裙" |

#### 4.7.3 SSE 流式推送协议
```
data: {"type": "parsing", "filters": {...}}
data: {"type": "product", "product": {...}}
data: {"type": "product", "product": {...}}
data: {"type": "summary", "total": 15, "platforms": {...}}
data: {"type": "done"}
```

#### 4.7.4 验收标准
- [ ] 用户输入筛选条件后，首先展示「正在解析您的需求...」状态
- [ ] 商品逐条流式出现在列表中，无需等待全部加载完成
- [ ] 全部推送完成后展示筛选结果汇总统计
- [ ] 筛选解析失败时自动降级为关键词正则匹配兜底

#### 4.7.5 空结果与边界场景
- **检索无结果**：若多平台检索后无可匹配商品，商品列表区域展示友好空状态插画与文案「暂未找到相关商品，试试修改关键词吧」，同时保留建议卡片区域供用户探索
- **筛选无结果**：若自然语言筛选后结果集为空，商品列表展示「没有符合条件的商品，试试放宽筛选条件」提示，并保留筛选输入框供用户快速修改
- **非商品图片**：若用户上传图片中不包含可识别商品，VLM 识别失败后展示「未识别到商品，请上传清晰的商品图片」并引导用户重试或改用文字搜索

### 4.8 设置与账户模块

#### 4.8.1 功能描述
设置页提供完整的用户偏好管理功能，包括个人信息编辑、登录/注册、外观主题切换、字体大小调节、缓存清理和消息通知偏好设置。所有设置通过 SharedPreferences 持久化，重启后保持。

#### 4.8.2 个人信息编辑
- 支持设置头像（从系统相册选取，自动压缩至 512×512）、昵称（单行文本）和个人简介（多行文本，最多100字）
- 未登录时个人资料卡片显示默认头像、昵称"SnapShop 用户"和邮箱占位
- 点击卡片的行为取决于登录状态：未登录跳转登录页，已登录跳转 `/profile` 个人中心页（收藏 + 浏览记录）。已登录时卡片显示从 `/user/stats` API 获取的收藏数和浏览数统计。
- 数据通过 SharedPreferences 持久化（profile_avatar / profile_nickname / profile_bio）

#### 4.8.3 登录/注册
- 对接后端 JWT 认证系统：输入手机号和密码，调用 POST /auth/login 接口，成功后 ApiClient 自动注入 Bearer token。注册调用 POST /auth/register。
- 登录后 isLoggedIn 持久化为 true，退出登录按钮显示
- 退出登录时弹出确认对话框，确认后清除所有用户数据并重置为默认值
- 支持登录与注册模式切换，中英文双语提示文案

#### 4.8.4 外观切换
- 底部弹窗提供三个选项：浅色模式、深色模式、跟随系统
- 选中项显示蓝色高亮 + 实心勾选图标
- 跟随系统模式下应用自动响应系统主题变化
- 设置持久化（theme_mode），动态切换 themeMode

#### 4.8.5 字体大小调节
- 底部弹窗提供三个档位：小(0.85x)、标准(1.0x)、大(1.15x)
- 每档显示"Aa"预览文字效果
- 选中后全应用所有文字即时按比例缩放
- 设置持久化（font_size）

#### 4.8.6 缓存清理
- 实时显示当前 Flutter 图片缓存占用大小（通过 PaintingBinding.instance.imageCache.currentSizeBytes 计算）
- 点击弹出确认对话框，确认后清除 imageCache
- 清理后 trailing 实时更新为"0 KB"

#### 4.8.7 消息通知偏好
- 底部弹窗包含两个 SwitchListTile 开关：
  - 推送通知（push_enabled）

### 4.11 主题与字体自适应系统

#### 4.11.1 功能描述
应用提供完整的暗色模式支持和全局字体缩放系统。通过 ThemeAwareColors + BuildContext 扩展实现上下文感知的动态颜色切换，所有 widget 通过 context.colors 和 context.fs() 自适应主题和字号变化。

#### 4.11.2 颜色自适应
- context.colors 根据当前 Brightness 自动切换浅色/深色色值
- 覆盖 12 种常用 UI 颜色（背景、卡片、文字、分割线、搜索栏等）
- 品牌色、语义色、平台色保持固定不变
- 深色模式背景色：#0F172A（主背景）/ #1E293B（卡片/表面）

#### 4.11.3 字体缩放
- context.fs(base) 自动乘以 FontSizeOption.scale
- 替代所有硬编码 fontSize，一处修改处处生效

#### 4.11.4 验收标准
- [ ] 深色模式下所有页面背景、文字、卡片、弹窗颜色正确适配
- [ ] 字体三档缩放全应用覆盖、无遗漏

### 4.12 国际化系统

应用内建中英文双语支持，通过 AppLocalizations + LocalizationsDelegate 实现。翻译键采用内联 Map 映射，getter 自动按当前语言返回对应文案。目前已覆盖 70+ 翻译键，涵盖全部 UI 文案。

## 5. 非功能需求

### 5.1 性能要求
| 指标 | 目标值 |
|------|--------|
| 图片上传耗时 | ≤ 2s（在 4G 网络下） |
| VLM 识别耗时 | ≤ 5s |
| 商品召回耗时 | ≤ 3s |
| 建议卡片生成耗时 | ≤ 2s |
| 自然语言筛选全流程 | ≤ 3s |
| App 冷启动 | ≤ 2s |
| 首屏看图耗时（TTI） | ≤ 300ms，上传同时用本地文件 Base64 回显预览图，防止白屏等待 |

### 5.2 兼容性要求
- **Android**：Android 8.0 及以上，覆盖 95% 活跃设备
- **iOS**：iOS 14.0 及以上，覆盖 95% 活跃设备
- **HarmonyOS**：HarmonyOS 3.0 及以上（远期扩展）
- **屏幕适配**：支持 5 英寸到 10 英寸所有主流屏幕尺寸

### 5.3 合规要求
- 完全禁用端侧 AI SDK，所有 AI 计算 100% 在云端完成
- 不编写任何网络爬虫，仅使用公开合法电商平台 API 或模拟数据
- 用户上传图片 7 天后自动清理，不永久存储
- 所有网络请求强制 HTTPS TLS 1.3

### 5.4 可用性要求
- 主链路可用性 ≥ 99.5%
- AI 服务异常时自动降级到规则兜底模式，核心功能不中断
- 支持弱网环境下的离线缓存，历史搜索记录本地持久化
